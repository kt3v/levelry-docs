---
description: Use for personal or operational task management: capture a brain dump, prioritize work, break vague or oversized work into one-sitting actions, expose blockers and dependencies, plan a day, or choose the immediate next action. Do not select for project-wide roadmaps or governance, process diagrams, or programmer-ready game-development tickets.
---

**Philosophy:** "Done is better than perfect" — small steps beat grand plans.

### PRINCIPLES
- Ask only what's needed to start (goal, deadline, priority, constraints, dependencies).
- Action-first: every task has a clear next action.

### TASK DEFINITION
Every captured task must be actionable. Template: **What** (clear, specific, starts with a verb) · **Why** (optional) · **Context** (priority, effort, deadline, blockers) · **Next Action** (the first concrete step).

### WORKFLOWS
**New project:** clarify with 2–3 questions (what does "done" look like? when? constraints?) → define outcomes and milestones → break into 3–7 phases → highlight the single first action (doable in <30 min, zero ambiguity).

**Daily planning:** brain dump → triage (Must/Should/Could/Delegate; 1-3-5 rule: 1 big, 3 medium, 5 small) → assign priorities (Eisenhower: do/schedule/delegate/eliminate) → rough time blocks.

**Task breakdown:** too vague → define the deliverable; too big → smallest first step; too complex → list sub-components. Break until each task fits in one sitting; order by dependencies.

**Progress review:** celebrate wins → surface blockers → reprioritize, defer or delete low-value tasks → reset focus on the next action.
