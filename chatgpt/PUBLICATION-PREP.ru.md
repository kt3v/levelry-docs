## Идентификаторы и иконки

Скачанный исходный личный manifest имеет имя
`dev-6abd5dfc6eb88191afa78e230b75891e` и версию `1.0.0`.
Его MCP app: `asdk_app_6abd5dfc6eb88191afa78e230b75891e`.
Публичный исходный пакет сохраняет имя `levelry`, версию `0.1.0`.

Для обновления этой личной карточки с сохранением идентификатора:

```sh
node scripts/package-plugin.mjs --private dev-6abd5dfc6eb88191afa78e230b75891e 1.0.4
```

Результат: `releases/levelry-plugin-1.0.4-personal-update.zip`.
Обычный `--private` создаёт пакет с именем `levelry`; при его загрузке
в существующую автоматически созданную карточку ChatGPT отвергает имя.
Версия 1.0.3 успешно импортирована после Refresh tools: описание, издатель Levelry,
Productivity, сайт, стартовые запросы и skill подтверждены в интерфейсе.
Отображение брендовой иконки отдельно требует проверки: сразу после
импорта карточка показала запасной значок глобуса. Это наблюдается и после
импорта в исходном Codex-формате с правильными путями PNG. Причина
не подтверждена; наличие файлов в ZIP не означает успешное отображение.
Скачанный обратно из ChatGPT пакет версии 1.0.2 сохраняет оба PNG,
правильные `logo`/`composerIcon` пути и исходные размеры файлов.

Обновление 1.0.4 заменило `logo` и `composerIcon` на контурный SVG;
Refresh tools выполнен после последнего серверного деплоя. Владелец
подтвердил правильную иконку в каталоге ChatGPT после перезагрузки страницы.
Отображение в desktop после перезапуска пока не подтверждено.

Архив обновления использует `.codex-plugin/plugin.json` и только `.app.json`
для уже зарегистрированного MCP, без повторного подключения через URL.
Публичный архив использует `plugin.json` и `mcp.json`, без private app mapping.
Изменение App description и Refresh tools в Manage app пересоздали стандартные поля карточки;
после этого полный пакет был импортирован заново. После изменений MCP app
повторно проверять сохранность package metadata.

Иконки пакета теперь обе используют `plugins/levelry/assets/sidebar-icon.svg`:
статический контурный знак, прозрачный фон, квадратные размеры 512×512.
Прежние цветные `logo.png` и `icon.png` остаются в assets, но manifest
больше не использует их для `logo` и `composerIcon`.
Иконка запуска панели задаётся отдельно в `openLevelry.icons`:
`https://levelry-server-hvyc5.ondigitalocean.app/chatgpt/icon.svg`.
Серверный маршрут раньше намеренно возвращал квадратики. Локальное
исправление использует брендовый SVG из фронтенда с квадратной областью;
см. `LevelryUnifiedServer/src/mcp/chatgptIcon.ts`. Коммит `a417d03` отправлен
в `master`; автоматический деплой завершён. Рабочий URL проверен: возвращает
брендовый SVG 512×512. Каталог инструментов использует `?v=2` для обновления
кэша. После визуальной проверки владельцем цветной SVG заменён на статический
контурный waiting-индикатор из `AIChat.tsx`: круг, треугольник и внутренний
круг, только `currentColor` и прозрачные внутренние области. Файл для
повторного использования: `plugins/levelry/assets/sidebar-icon.svg`.
Каталог инструментов нового варианта использует `?v=3`.
Коммит контурного варианта `e3990d3` отправлен в `master`; второй деплой
завершён, публичный URL проверен и возвращает контурный SVG без заливок.
Refresh tools личного подключения выполнен после первого деплоя, повторный
вызов `openLevelry` успешен. Проверка отображения иконки в desktop-панели
остаётся отдельным шагом. `global` и `thread` entrypoints уже объявлены в коде.
Владелец пока видит прежние квадратики в desktop-панели до перезапуска;
кэш клиента — гипотеза, не подтверждённая причина.

## Демонстрационные данные

В подключённом аккаунте создан отдельный **Levelry Review Demo**,
projectId `2801d87b-b2a4-41b9-9402-22aec9fdc996`. Четыре документа:
Research → Launch Plan → Prototype → Release, три связи `flow`.
Содержание вымышленное. Создание проекта, объектов и связей прошло успешно;
Launch Plan прочитан обратно через MCP. В браузерном редакторе вручную
отмечен пункт `Confirm the prototype scope`; повторное чтение через MCP
подтвердило `[x]` и ревизию проекта 8. Объекты и связи видны в редакторе.
Создание не меняло активный проект других разговоров (`makeActive: false`).
Это проект владельца для подготовки материалов, не готовый reviewer account.

Настройки ChatGPT показывают предупреждение, что app-only инструмент
`renewLevelrySession` не может отображать widget. Это ещё не подтверждённый
сбой: инструмент предназначен для обновления внутренней сессии. Проверить
его вызов из редактора при истечении сессии перед ревью.

## Скриншоты

По [точным требованиям](https://developers.openai.com/plugins/deploy/submission-errors)
скриншоты для custom UI необязательны. Если добавлять: PNG/JPEG,
ширина 706 px, высота 400–860 px, один на каждый стартовый запрос.
[Guidelines](https://developers.openai.com/plugins/plugin-guidelines) отдельно
говорят, что в каталоге скриншоты больше не показываются. Проверить текущую
форму портала перед финальной отправкой.

Снять реальные результаты на демонстрационном проекте:

1. `Open my Levelry canvas.` — редактор, выбранный проект, документы.
2. `Organize my ideas into a diagram in Levelry.` — результат реальных
   инструментов ChatGPT с объектами, связями и документами.

Добавлять `interface.screenshots` только после создания файлов. Макеты
не заменяют снимки работающего интерфейса.

## Сценарий видео

Предлагаем 4–6 минут; это план записи, не требование по длительности.
Использовать вымышленные данные, не показывать пароль и токены.

1. Открыть Levelry Canvas из боковой панели, показать логотип и выбор
   проекта, затем открыть панель рядом с беседой.
2. Выполнить `List my Levelry projects.` и показать доступные проекты.
3. Выполнить `Create a new Levelry project called Review Notes.`;
   выбрать созданный проект.
4. Выполнить positive case добавления Launch Plan из manifest,
   открыть документ и показать сохранённый текст.
5. Выполнить positive case поиска и чтения Launch Plan.
6. Создать небольшую диаграмму стартовым запросом. Переместить объект,
   изменить документ вручную, перезагрузить и проверить сохранение.
7. Показать три negative cases из manifest: чужой приватный проект,
   запись при read-only consent и неподдерживаемая отправка email.
8. Проверить два проекта в разных беседах, темы и целевые платформы.

После записи добавить реальный доступный ревьюеру URL в
`extensions.com.openai.review.demo_recording_url`. Видео для MCP-ревью
обязательно. Данные тестового аккаунта вводятся отдельно в приватные
поля портала. Основной подробный прогон — [REVIEW-CASES.md](REVIEW-CASES.md).

## Что требует данных владельца

- Verified имя индивидуального издателя или компании.
- Реальные support/privacy/terms страницы. Для privacy нужны фактические
  сроки хранения, обработчики, порядок удаления и контакт владельца;
  этих сведений в репозитории недостаточно для готового документа.
- Отдельный reviewer account с примером данных и доступным ревьюеру входом.
- Доступ к деплою для иконки, UI domain и позднее domain challenge.

Не отмечать всё готовым до проверки установки с нуля, обоих запусков,
иконок, сохранения, read-only, отзыва доступа, изоляции проектов,
ошибок сети и восстановления сессии.
